    How This Book Works

    Three ideas that make everything after this page easier to follow.

    Read → Run → Break → Explain

    You are not expected to memorize syntax. You are expected to type every example yourself, run it, and then break it on purpose to see what the error looks like. That last step matters more than people think — a data engineer's real job is reading error messages calmly and figuring out what they mean.

    1. Code Along

    Don't just read the code blocks — retype them in your own editor. Typing builds muscle memory that reading never will.

    2. Break It on Purpose

    Misspell a column name. Remove a comma. Read the error. This is how you stop being afraid of red text.

    3. Explain It Back

    After each lesson, say out loud (or write one sentence) what the code does. If you can't, re-read the lesson.

    Meet BrightCart: Your Case Study

    Every code example, every SQL query, and every mini-project in this book — across all three phases — uses the same small dataset: a fictional online store called BrightCart. Real data engineering work is never a random toy example per lesson; you follow one system end to end. This book does the same thing on purpose.

    BrightCart sells electronics, home goods, apparel, and books. Its data has exactly the shape you'll meet in a real job: customers who sign up, products with prices, orders that get placed, and order line items — plus some orders that are still pending, cancelled, or refunded, because real businesses aren't tidy.

    The BrightCart schema — one customer places many orders, one order can contain many order_items, and every order_item points at one product.

    TableGrain (one row =)Used to teach
    customersone person who signed upfiltering, joins, dimension tables
    productsone item BrightCart sellsjoins, categories, pricing logic
    ordersone checkout eventdates, status, aggregation
    order_itemsone product inside one orderjoins, SUM/quantity math, fact tables

    Why a fake store and not a "real" public dataset?

    Public datasets are messy in ways that distract from the lesson at hand. BrightCart is small enough to hold in your head (16 customers, 14 products, 45 orders) but shaped exactly like production data, including a deliberately messy version you'll clean in Phase 2. You always know what the "right" answer should look like, which is how you learn to spot when your own query is wrong.

    Why Start With Tools, Not Code?

    A carpenter doesn't start a project by learning to swing a hammer mid-job — they set up the workbench first. Data engineers do the same. Before you write a line of Python or SQL, you need a place to write it (an editor), a way to run it (an interpreter), a way to talk to your computer directly (a terminal), and a way to save your progress so nothing is ever lost (version control).

    Python 3

    The language interpreter — turns the code you write into instructions your computer executes.

    VS Code

    The IDE (editor) — where you write, run, and debug every script and query in this book.

    The Terminal

    The command line — how you navigate folders and run programs without clicking icons.

    Git & GitHub

    Version control — saves checkpoints of your work and gives you a public portfolio.

    Tool Spotlight: Python

    15 min

    Tool Spotlight

    Python 3

    The programming language you'll use for almost everything in this bootcamp.

    What it is

    Python is an interpreter: a program that reads your .py file line by line and executes it immediately. There's no separate "compile" step, which is why it's a popular first language.

    Why data engineers use it

    Nearly every data tool you'll touch later — pandas, Airflow, PySpark — is a Python library. Learning Python fundamentals now is what makes all of Phase 2 and 3 possible.

    How to get it running

    1. 1
      Go to python.org/downloads and download the latest Python 3 installer for your OS.
    2. 2
      Windows: during install, tick "Add python.exe to PATH" before clicking Install — this single checkbox prevents 90% of beginner setup issues.
    3. 3
      Mac: the installer works out of the box; Terminal.app already knows where Python lives once installed.
    4. 4
      Restart your terminal, then verify the install (see "Try it" below).

    Try it

    terminal
    $ python --version
Python 3.12.4

$ python3 --version   # Mac/Linux sometimes need python3, not python
Python 3.12.4
    Common snag: If python --version says "command not found," the PATH checkbox above was likely missed. Re-run the installer and choose "Modify" to fix it — no need to uninstall first.

    Tool Spotlight: VS Code

    10 min

    Tool Spotlight

    Visual Studio Code (VS Code)

    A free code editor with the exact features a data engineer needs — nothing more, nothing less.

    What it is

    VS Code is a text editor built for writing code: it colors your syntax, catches typos before you run anything, and has a built-in terminal panel so you never have to alt-tab away from your code.

    Why data engineers use it

    You'll live inside VS Code for all three phases — writing Python scripts, SQL files, Airflow DAGs, and Dockerfiles all in one window, with Git built directly into the sidebar.

    How to get it running

    1. 1
      Download it from code.visualstudio.com and run the installer (default options are fine).
    2. 2
      Open VS Code, click the Extensions icon in the left sidebar (four squares icon).
    3. 3
      Install the Python extension (by Microsoft) — enables run/debug and autocomplete.
    4. 4
      Install SQLTools (optional but recommended) — lets you run SQL queries against PostgreSQL from inside VS Code later in this chapter.

    Try it

    terminal
    # From a terminal, inside any project folder:
$ code .
# The dot means "open the current folder in VS Code"
    Common snag: If code . doesn't work, open VS Code manually once, press Cmd/Ctrl+Shift+P, type "Shell Command: Install 'code' command in PATH", and select it.

    Tool Spotlight: The Terminal

    15 min

    Tool Spotlight

    The Terminal (Command Line)

    A text-based way to control your computer — no mouse required.

    What it is

    The terminal is a program that accepts typed commands instead of clicks: moving between folders, running scripts, and installing tools all happen here. On Windows it's usually PowerShell or the "Terminal" app; on Mac it's Terminal.app; VS Code has one built in under the menu Terminal → New Terminal.

    Why data engineers use it

    Data engineers live in the terminal because most real tools — Git, Docker, cloud CLIs, Airflow — are only fully controllable from the command line. There is no "skip this" option later in the bootcamp, so it's worth getting comfortable now.

    How to get it running

    1. 1
      You already have one — open VS Code and go to Terminal → New Terminal (or press Ctrl+`).
    2. 2
      Confirm you're in your home folder by running pwd (Mac/Linux) or cd with no arguments (Windows) — it prints your current location.
    3. 3
      Practice moving around using the commands in the table below before continuing.
    CommandWhat it doesExample
    pwdPrint Working Directory — shows where you arepwd
    cdChange Directory — move into a foldercd Desktop
    cd ..Move up one foldercd ..
    ls / dirList files in the current folder (Mac/Linux vs Windows)ls
    mkdirMake a new foldermkdir de-bootcamp
    python file.pyRun a Python scriptpython hello.py
    terminal — moving into a new project folder
    $ pwd
/Users/ana/Desktop

$ mkdir de-bootcamp
$ cd de-bootcamp
$ pwd

    Beginner trap: typing paths with the wrong slashes

    Mac/Linux use forward slashes (data/raw); Windows PowerShell also accepts forward slashes in most commands, so when in doubt, use / — it works almost everywhere in this book.

    Tool Spotlight: Git & GitHub

    20 min

    Tool Spotlight

    Git & GitHub

    Git is your project's time machine. GitHub is where that history becomes a public portfolio.

    What it is

    Git is a program installed on your computer that tracks every change you make to a project folder, in checkpoints called commits. GitHub is a website that stores a copy of that history online, so employers, teammates, and future-you can see it.

    Why data engineers use it

    Every mini-project and portfolio project in this bootcamp gets committed to Git and pushed to GitHub. Your GitHub profile is your resume as a career shifter — it's proof you can actually build things, not just say you can.

    How to get it running

    1. 1
      Download Git from git-scm.com/downloads and install with default options.
    2. 2
      Verify it worked: run git --version in your terminal.
    3. 3
      Create a free account at github.com if you don't already have one.
    4. 4
      Tell Git who you are (one-time setup, shown in "Try it" below) — every commit gets stamped with this name and email.

    Try it

    terminal — one-time setup
    $ git --version
git version 2.44.0

$ git config --global user.name "Ana Dela Cruz"
$ git config --global user.email "ana.delacruz@example.com"
    Common snag: Don't skip the git config step — without it, your first commit will fail with an "author identity unknown" error.

    How Git Actually Works

    Git moves your work through three places. Understanding this diagram now will save you real confusion later — almost every Git error a beginner hits comes from not knowing which of these three states their file is in.

    A file moves left to right: you edit it, you `add` it to staging, you `commit` it to local history, you `push` it to GitHub.

    TermMeaning
    Repository (repo)A project folder that Git is tracking.
    CommitA saved checkpoint, with a short message describing what changed.
    Stage / git addMarking which changed files should go into the next commit.
    PushUploading your local commits to GitHub.
    CloneDownloading a copy of a GitHub repo onto your computer.
    the five commands you'll type more than any others in this bootcamp
    git init                        # start tracking this folder
git status                      # what changed since the last commit?
git add .                       # stage everything that changed
git commit -m "first commit"    # save a checkpoint
git push                        # upload to GitHub

    A daily habit, not a one-time event

    Run git add . && git commit -m "..." every time you finish a small, working piece of code — not just at the end of the day. Small commits with clear messages are what a real engineering team (and a hiring manager skimming your GitHub) expects to see.

    Activity: Your First Repository

    15 min
    Hands-on Activity 1

    Create the de-bootcamp Project and Commit Hello Data World

    Put everything from this chapter together: create a folder, initialize Git, write one line of Python, and push it to GitHub.

    1. Open a terminal and run mkdir de-bootcamp && cd de-bootcamp.
    2. Run git init to start tracking the folder.
    3. Open the folder in VS Code with code .
    4. Create a new file named hello.py containing one line: print("Hello, BrightCart!")
    5. Run it from the VS Code terminal: python hello.py — confirm it prints the message.
    6. Stage and commit: git add . && git commit -m "add hello script"
    7. On GitHub.com, create a new empty repository named de-bootcamp, then follow the "push an existing repository" instructions GitHub shows you to connect and git push.

    Deliverable: A GitHub repository with one commit and a working hello.py file — this is repo #1 of your portfolio.

    Chapter 1 Checklist — before moving on, you should be able to:

    • Run python --version and see a version number, not an error
    • Open a folder in VS Code using code .
    • Move between folders in a terminal using cd, ls, and mkdir
    • Explain the difference between git add, git commit, and git push
    • Have a GitHub repository containing your first commit
