    The Production Mindset

    Everything in this phase is really one idea, applied three ways: a pipeline isn't finished when it works once. It has to rerun safely, log enough to debug itself, fail loudly on bad data, and be easy for someone else to deploy and understand. Airflow, Spark, and Docker are three different answers to "how do I make that actually true?"

    Orchestration With Airflow

    Phase 2's pipeline runs by hand. Airflow is what runs it for you, on a schedule, with retries, while you sleep.

    Why Orchestration Exists

    A single pipeline script is fine until you have five of them, some depending on others finishing first, all needing to run at specific times, with someone needing to know immediately when one fails. Orchestration is the layer that manages all of that — scheduling, dependencies, retries, and visibility.

    Your First DAG

    dags/first_pipeline.py
    from airflow import DAG
from airflow.operators.empty import EmptyOperator
from datetime import datetime

with DAG(
    dag_id="first_brightcart_pipeline",
    start_date=datetime(2026, 1, 1),
    schedule="@daily",
    catchup=False
) as dag:
    start = EmptyOperator(task_id="start")
    finish = EmptyOperator(task_id="finish")
    start >> finish
    TermMeaning
    DAGa workflow definition — a set of tasks and the order they run in
    Taskone unit of work inside a DAG
    Operatora template for a kind of work (run Python, run Bash, etc.)
